## User outcome

An agent starts a queued check, retains its exact job ID, and receives a bounded result that distinguishes a finished job from an expired observation. It can read several jobs together and continue a log without replaying old output. The CLI explains its actual commands. Waiting requires no rapid model polling. Where an authenticated Codex completion route is available, one completion resumes the exact owning thread.

For example, `qex submit --agent --cpu 2 --mem 3GB -- make test` uses minimal environment capture, waits for a bounded observation, and returns the same compact JSON envelope as `qex status ID --agent --wait`. A timeout leaves the job active and returns its ID and a bounded command for reattachment. Legacy invocations retain their output shape and exit-code meanings.

## Architecture and limits

Extend the existing Clap CLI, status reader, native wait and log selector. Reuse the persistent job records, existing coordinator protocol and stop-hook/event machinery. Avoid a second scheduler, controller, generic plugin framework, whole-environment capture or external service.

The agent response is opt-in and versioned. Its minimal record excludes full command/environment/process ancestry unless explicitly requested. Selectors reject unknown fields. Defaults bound output; a budget smaller than required metadata yields a clear error rather than malformed JSON or silently omitted jobs. Logs use task-bound offsets and detect retention rewrites; cursors are data, not file paths. No new persistent cursor database is required.

Wait deadlines govern observation, not job termination. RPC limits bound coordinator operations without turning long job waits into short RPC failures. Multi-job output does not grant ownership or permission to stop any job. Existing exit codes, deduplication, retry and cancellation behavior are preserved.

The notification route is `--notify-codex ABSOLUTE_SOCKET` on submit, with an optional explicit absolute `--codex-client EXECUTABLE`; otherwise resolve the installed codex executable from the caller's PATH once and retain its absolute path. Capture and validate the caller's exact CODEX_THREAD_ID before admission. An absent/malformed thread ID, invalid endpoint or executable fails before submission. The caller explicitly supplies the public local socket of that owning app-server; qex does not discover endpoints, attach to unrelated controllers, infer a thread from cwd/name/PID, or access private Padavan provider sockets. Bind the registration to the full job UUID and immutable thread/endpoint/client tuple. Different or unbound dedupe owners cannot silently acquire or replace a route.

At terminal completion, run the public argv `codex queue --remote unix://SOCKET --thread EXACT_UUID --message FIXED_COMPLETION_TEXT`. The live installed 0.164.0 probe established that adding a queued submission to an idle owned thread automatically starts generation, produces a completed turn and the expected reply. There is no qex model polling loop and no new Codex controller. Active-thread delivery stays queued for native processing; do not replace it with an unconditional competing turn/start. Report enqueue separately from actual model completion, which final acceptance observes. The completion text identifies itself as an untrusted qex job observation and includes only job UUID, terminal state/code and a result-retrieval argv, never a command, environment or raw log body.

Store one private registration/attempt/outcome beside the job record under existing job-directory retention and cleanup. The submitting client writes the immutable route and reconciles already-terminal status. All supervisor/coordinator terminal paths dispatch through existing terminal-hook coverage independently of global hook filtering/hook.ran. An atomic per-job claim/lock prevents duplicate sends across registration/completion races. Keep dispatch outside scheduler critical paths, with bounded time/output; notification failure never changes the job outcome. Persist pending/attempt/enqueued/failure/unknown evidence atomically. A timeout, crash or lost reply after possible dispatch remains visibly unknown and is never automatically resent with a new intent. The installed Codex queue CLI does not expose a public exact retry binding; do not invent one or promise crash-proof exactly-once wakeup. Record bounded client outcome evidence and expose notification state to status readers. Endpoint disappearance/replacement and malformed client outcomes must be visible, not an alias or transport fallback.
